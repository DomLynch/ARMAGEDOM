## Selection and capacity

Copy/sort FULL keys by code-unit order; no caller array mutation, actorID, spawn order, live/dead flag, RNG, global cache or run seed. Seed area+library version establishes deterministic top-ID priority and tie order. First unused top is the priority head; each later top maximizes its minimum squared Oklab distance from all selected tops. Uses published public-domain linear-sRGB matrices from [Bjorn Ottosson](https://bottosson.github.io/posts/oklab/#converting-from-linear-srgb-to-oklab). Priority hashes are NOT modulo per-actor assignments, so hash ties cannot duplicate tops: every top is removed once and ties resolve by stringID.

For current6/9/9 and up to50 residents with the50-top library, topIDs and complete outfits are unique across ordinary+Crooked+corpses in one area pool. Approved trousers may repeat. Above available top count, cycle the already selected deterministic order; rotate only that top's approved trousers each complete cycle. With two pants per top, later cycles can produce distinct outfits but repeats eventually occur; no impossible uniqueness claim. Work bounded by max50-colour selection plus finite roster sorting/mapping, no rejection/retry loop. Zero residents returns empty Map after library validation. Library order/pairing-list order do not change output.
