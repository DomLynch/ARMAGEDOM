## What
Living residents are built **without** finisher geometry. After arrival an idle pump prepares it in small slices; an alerted resident jumps the queue. Takes the finisher-presentation prep (victim-floor 1.5-3.2 s + crown-cut 1.8-2.0 s, about 85% of the CPU block in the travel pause, see #97) out of the pause and out of cold load. On by default; the budgets live in data.

- `finisher-presentation.js`: `deferPreparation` builds only the ordinary death; `prepare()` (a step generator) adds run-through grounding, head, crown, opened body and arm. The recipes join `support` (the array the sim holds by reference) only once each is fully prepared. An abandoned `prepare()` frees its partial pieces and restores the base list.
- `engine/finisher-prep-pump.js`: nothing in the first `startDelayMs` after arrival; at most `sliceMs` per frame; quiet for `backoffMs` after any frame longer than `backoffFrameMs`; alerted residents first, then nearest; a resident that dies or leaves mid-prep is dropped. Each slice puts the rig back into its build-time pose and restores the live pose afterwards (the bakes read the pose, and a live resident animates between frames).
- `finisher-grounding.js`: re-poses the rig after every resume (it yielded mid-sample before, which was only safe while nothing else drove the rig).
- `actors.js`: defers living `hollow-scavenger` residents only; corpses restored from a run still prepare eagerly; adds `completeFinisherPreparation()` / `deferredFinisherSteps()` for tests and tools.
- Budgets in `engine/finisher-data.json` -> `preparation.deferred` (validated in `finisher-data.js`): `enabled`, `startDelayMs` 1000, `sliceMs` 2, `backoffFrameMs` 25, `backoffMs` 2000. Off switch: `enabled: false`.

## The three things Lead asked to see stated
1. **Save:** `entity.finisher.recipeId` and the corpse finisher state are **not written into the save**. No save module (`run-core`, `run-save-state`, `run-state`, `save-eras`, the `*-core` stores) references `finisher`; `travel.js` only shifts the in-memory part timers. So there is nothing for an old save to disagree with, and no recipe that "isn't prepared yet" can be loaded from storage. The full Web suite (which includes the rollback-saves and save-restore tests) is run on the final head, see Tests.
2. **Kill before prep is done:** the sim picks a recipe only from `support`, which lists only fully prepared recipes, so it falls to the ordinary or native death (`bullet-native-collapse` etc.). The presentation plays a complete ordinary death. **Nothing is ever built on the spot**, and the body is never missing (test: `a kill before preparation is done falls back to a plain death and never builds anything on the spot`: no parts detach, cost 0, zero owned geometry).
   Tier note: this IS sim-visible. `entity.finisher.recipeId` for a very fast kill (within about a second of arrival, or before the pump reached that resident) can differ from what an up-front build would pick, because the recipe list depends on prep timing. Presentation only; no hp, damage, loot or save difference.
