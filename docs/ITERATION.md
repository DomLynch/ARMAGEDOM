# ARMAGEDOM iteration contract — owner approved2026-10-02

Expect frequent small changes. Use the smallest suitable update path:

| Change | Intended workflow |
| --- | --- |
| Camera zoom/angle, lighting, balance | Change persistent settings and refresh the running development game. |
| Move/rotate a world object | Edit saved layout and refresh the affected area; recheck collision. |
| Another instance of a building | Place a reusable asset; no new behaviour code. |
| New monster model or region | Build and deliver compatible content, reloading the area when needed. |
| Trading or a new combat mechanic | Change code, test, release affected client/server software. |

These are target capabilities. Persistent live tuning and content delivery are
not implemented in the current prototype. Saved source, imported assets, running
development state and packaged releases require separate verification.

The first London area uses the owner-supplied Westminster image as a visual target
for editable3D props, explicitly chosen over a fixed-picture2.5D scene. Preserve
the current camera/controls and bounded combat footprint. Reuse modular props for
cracked road, damaged masonry, wrecked red bus, sandbags, barriers and firelight.
Gameplay period:2029–2030. The untouched older story source remains reference.
The hero becomes a human vagrant; do not claim the current knight is converted.
